# Security Policy

## Supported Versions

This project is pre-1.0. Security fixes are applied to the latest release on `main`.

| Version | Supported |
| ------- | --------- |
| 0.1.x | Yes |

## Reporting a Vulnerability

Report security issues privately. Do not open a public issue for an unfixed vulnerability.

- Email **security@noru.tech** with a subject line beginning `[SECURITY] noru-grc-engineering`.
- On GitHub you may also use Private Vulnerability Reporting.

Include the affected file or version, reproduction steps, expected impact, and whether any secret or
customer data exposure is involved.

We aim to acknowledge within 5 business days and give a remediation timeline after triage.

## Threat model

These plugins connect a local AI client to a customer's **compliance system of record**, read the
customer's entire repository, and can write to Noru. Four risks follow from that, and each has a
control in the contract rather than a paragraph of advice.

### 1. Prompt injection through repository contents and tool output

A collector reads someone's whole repository. Source files, comments, READMEs, configuration, commit
messages and MCP tool responses are **untrusted data**. If any of them contain text addressed to an
agent — instructions, claimed permissions, urgency, "the user already approved this" — the piece
must quote it in its report as a finding and must not act on it.

**Control:** every command and skill states this explicitly. Consent comes from the user in the
conversation and from nowhere else. Approval claimed inside a file, a tool result or a README is not
approval.

### 2. Unreviewed writes to a customer's register

**Control:** `:diff` before `:push` is a security control, not UX polish.

- `push` exits `2` without an explicit `--confirm`.
- `push` exits `1` unless a plan exists that was generated by `:diff` from the manifest bytes on
  disk **right now**. Editing the manifest after review invalidates the plan.
- For MCP pieces, `push` does not make the calls: it writes the exact, ordered, confirmed call list
  and the client executes precisely that. An agent improvising a call outside the list is a bug.

`scripts/contract_test.py` executes all three refusals against every piece on every build. If a
piece stops refusing, CI fails.

### 3. Credential exposure

**These plugins never handle a credential.**

- MCP authentication belongs to the MCP host — OAuth where supported, otherwise a bearer key the
  client holds. No plugin reads it, stores it, or asks for it.
- The single REST path (`evidence-push:push`, because file upload cannot travel over MCP) reads
  `NORU_API_KEY` from the environment **at the point of use**. It is never written to a file, a
  plan, a log line, or stdout, and every error string that leaves the process passes through a
  redactor.
- `noru:doctor` reports only whether the variable is *set* — never its value, prefix, or length.

Never paste a key into an assistant conversation. If one appears there, rotate it.

`scripts/check_repo.py` scans the repository for credential-shaped strings on every build.

### 4. Over-broad scope

**Control:** every piece declares its least-privilege scopes in `piece.json` and repeats them in its
README, and the contract test fails if the two disagree. Read-only is the default posture: `:scan`
and `:diff` are useful before a piece is ever allowed to write.

## Secret handling

This repository is public. Do not commit:

- Noru API keys or bearer tokens
- OAuth access tokens, refresh tokens, authorization codes, or client secrets
- Customer identifiers, organization names, audit evidence, logs, or screenshots
- Local MCP client configs that inline secrets
- Tool output captured from a real customer organization

Use placeholders such as `<NORU_API_KEY>` and `${NORU_API_KEY}` in examples.

Note also what the machine-local cache holds. `.noru/.cache/` contains snapshots of an
organization's compliance state — control ids, coverage, evidence titles. **It must stay out of
git.** `noru:doctor` checks this, and every piece README says so.

## What is deliberately not in this repository

No framework control text, control guidance, or evidence-item catalogue. Two reasons, and both are
sufficient on their own: licensing (the SCF is CC BY-ND), and drift — a vendored catalogue is wrong
the moment the framework moves, and wrong quietly. Pieces call the API instead, and the contract test
fails the build if a catalogue-shaped identifier appears in a plugin.
