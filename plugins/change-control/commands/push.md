# /change-control:push

**Writes to Noru.** Adds `write:evidence` and `write:risks`.

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/push.mjs" --repo=<repo> --confirm
```

This refuses without both `--confirm` **and** a plan generated by `:diff` from the manifest
currently on disk. Editing the manifest invalidates the plan; run `:diff` again and read it again.

Immediately before running it, call `findOrganization` through the connection that will execute the
calls and refresh only `connection` in `.noru/.cache/noru-state.json`. The command also refuses an
organization, endpoint, scope, repository, plugin-version or expiry mismatch.

Execute exactly the calls the plan lists, in order, and nothing else. Where an operation carries
`depends_on`, substitute the named field from the result of the operation it points at — that is the
evidence id, which does not exist until the create runs.

Before executing `createEvidence`, inspect the connected tool schema. When it exposes
`idempotencyKey`, use the call's normal `arguments`. On an older deployment that does not expose
that field, use `compatibility.arguments` instead and report that the marker-probe fallback was
used. Do not silently remove any other argument.

## Before you confirm

- Every `needs_review: true` is gone, and gone because somebody decided — not because it was
  deleted to make the validator quiet.
- Every exception has a real owner. A name that cannot be asked what it was thinking is not an owner.
- The findings about to be pushed `resolved` really are fixed. Closing a finding is a claim.
- The window is the one you meant. A record filed under the wrong quarter covers neither.

Nothing here reads, writes or logs a credential. Authentication is the MCP client's job.
